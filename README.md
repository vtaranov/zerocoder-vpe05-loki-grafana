# VPe05 · Мониторинг и логирование: Loki + Grafana

Учебный стек: тестовое HTTP-приложение отправляет структурированные события напрямую в Loki через `POST /loki/api/v1/push`. Grafana показывает последние события в таблице и распределение по уровням в круговой диаграмме. Источник данных, дашборд, переменные и автообновление создаются автоматически из файлов в Git.

## Работающий стенд

- [Дашборд Grafana](http://159.194.202.109:3000/d/vpe05-logs/vpe05-loki-grafana) — просмотр без входа, права Viewer.
- [Тестовое приложение](http://159.194.202.109:18085/).
- [Health приложения](http://159.194.202.109:18085/health).

Стек работает на учебном VPS Ubuntu 24.04 с 1 vCPU и 2 ГБ RAM. Доступность ссылок зависит от того, оставлен ли стенд запущенным. Все события синтетические. Анонимный посетитель может смотреть дашборд, но не редактировать его и не управлять Grafana.

## Запуск

Нужны установленные Docker Engine, Docker Compose и Python 3.10+ для вспомогательных скриптов. Python внутри приложения поставляется Docker-образом. Сторонние Python-пакеты не требуются.

```bash
git clone https://github.com/vtaranov/zerocoder-vpe05-loki-grafana.git
cd zerocoder-vpe05-loki-grafana
python3 scripts/init_env.py
docker compose config --quiet
docker compose up -d --build
python3 scripts/verify_stack.py
```

`init_env.py` один раз создаёт `.env` со случайным паролем администратора и правами `0600`. Повторный запуск не перезаписывает пароль. Для изменения портов добавьте в `.env` значения из `.env.example`. Файл `.env` исключён из Git и Docker build context. Не запускайте `docker compose config` без `--quiet` при записи публичных логов: развёрнутая конфигурация содержит пароль.

Откройте `http://localhost:3000/d/vpe05-logs/vpe05-loki-grafana` и `http://localhost:18085/`. При запуске на VPS замените `localhost` на IP сервера. Порт приложения можно изменить переменной `APP_PORT`; ссылку на Grafana в HTML при нестандартном `GRAFANA_PORT` также следует изменить.

## Что входит в Compose

| Сервис | Версия | Назначение | Лимит RAM |
| --- | --- | --- | --- |
| `loki` | 3.7.8 | Один процесс, TSDB v13, локальное хранилище | 512 MiB |
| `grafana` | 13.2.4 | Источник Loki и дашборд | 384 MiB |
| `demo-app` | Python 3.13.13 Alpine | HTTP API и фоновый генератор | 96 MiB |

Лимиты — верхняя граница, а не постоянно занятая память. Loki слушает порт 3100 внутри Compose, наружу он опубликован только на `127.0.0.1`. Приложение и Grafana обращаются к нему по имени `loki`. Дополнительные агенты, Promtail, Prometheus и внешние базы данных не нужны.

Официальный образ Loki не содержит shell/HTTP-клиента, поэтому его готовность проверяет приложение через HTTP `/ready`, а полный стек — скрипт `verify_stack.py`. У приложения есть собственный Docker healthcheck. Фоновая генерация начинается после готовности Loki; ошибки отправки ограничены таймаутом в две секунды.

## Часть 1. Источник данных

Файл `grafana/provisioning/datasources/loki.yaml` создаёт источник с UID `loki` и адресом `http://loki:3100`.

Для проверки через интерфейс войдите администратором с данными из локального `.env`, откройте **Connections → Data sources → Loki → Save & test**. Provisioning управляет настройками источника, поэтому редактирование его полей отключено. Проверка здоровья источника выполняется запросом `GET /api/datasources/uid/loki/health`; этот же механизм вызывает `verify_stack.py` с авторизацией администратора.

Пароль стенда хранится на VPS в `/opt/vpe05-monitoring/.env`; в репозитории и скриншотах пароля нет. Файл предназначен владельцу сервера и доступен через его существующее SSH-подключение.

## Часть 2. Дашборд

Дашборд хранится в `grafana/dashboards/vpe05.json`. На нём ровно две панели:

1. **Последние логи** — таблица со временем, уровнем, сообщением, маршрутом и ID запроса. JSON из строки лога разбирается преобразованием Extract fields.
2. **Распределение по уровням** — кольцевая круговая диаграмма с количеством и долей INFO, WARNING и ERROR за выбранный период.

Переменные: `$app` (приложение) и `$level` (один, несколько или все уровни). По умолчанию выбран период 15 минут, автообновление каждые 15 секунд, часовой пояс Europe/Moscow.

Запрос таблицы:

```logql
{app="$app", level=~"$level"}
```

Запрос круговой диаграммы:

```logql
sum by (level) (
  count_over_time({app="$app", level=~"$level"}[$__range])
)
```

Используется Instant query и `$__range`, чтобы диаграмма считала события за весь выбранный период. Переключение периода и фильтра уровня применяется к обеим панелям. Для изменения дашборда отредактируйте JSON в Git; Grafana перечитает его в течение 30 секунд. Изменения через интерфейс для этого provisioned-дашборда отключены.

## Часть 3. Отправка логов

В `app.py` функция `send_log_to_loki` формирует JSON с `streams`, метками `app`/`level` и парами `[timestamp, message]`. Timestamp — строка с Unix-временем в наносекундах. HTTP 204 от Loki подтверждает приём. Сообщение — JSON с текстом, уровнем, UTC-временем, маршрутом и ID запроса. ID и маршрут хранятся в сообщении, чтобы не увеличивать число индексируемых потоков.

| Маршрут | HTTP | Уровень |
| --- | --- | --- |
| `/` | 200 | INFO |
| `/api/info` | 200 | INFO |
| `/api/warning` | 200 | WARNING |
| `/api/error` | 503, намеренная учебная ошибка | ERROR |
| неизвестный путь | 404 | WARNING |
| `/health` | 200 | Не создаёт логов |

Каждые 15 секунд приложение также создаёт фоновое событие. При старте отправляет по одному сообщению каждого уровня, чтобы обе панели сразу имели данные. Если Loki недоступен, обычный запрос продолжает обрабатываться, а JSON-ответ показывает `log_sent: false`.

```bash
curl http://localhost:18085/api/info
curl http://localhost:18085/api/warning
curl -i http://localhost:18085/api/error
```

## Проверки

```bash
python3 -m unittest discover -s tests -v
python3 scripts/verify_stack.py
# Дополнительно: перезапуск только этого стека с проверкой сохранности события
python3 scripts/verify_restart.py
docker compose ps
docker stats --no-stream
```

Семь тестов проверяют контракт Loki, время в наносекундах, таймаут/ошибку отправки, HTTP-маршруты, уровни и работоспособность приложения при сбое логирования.

`verify_stack.py` проверяет готовность сервисов, адрес источника и его health check, доставку трёх уникальных ID запросов из приложения до Loki, LogQL-агрегацию по уровням, фильтры и доступ Viewer к двум панелям. Учебный HTTP 503 от `/api/error` ожидаем и не означает неисправность стенда.

GitHub Actions запускает те же тесты и поднимает весь Compose-стек на отдельном GitHub runner. Доступ к VPS и его секретам для CI не нужен; автоматический деплой на VPS не настроен.

## Хранение и обслуживание

- Данные Loki и Grafana сохраняются в отдельных именованных Docker volumes.
- Loki настроен на хранение 24 часа. Compactor удаляет старые данные асинхронно, с дополнительной задержкой два часа; это не жёсткая квота диска.
- Контейнерные stdout-логи ротируются: до двух файлов по 5 MB на сервис.
- На небольшом VPS следует контролировать `df -h /` и `docker system df`; Loki не удаляет файлы автоматически по порогу свободного места.
- Открытая Grafana даёт только Viewer-доступ к синтетическим данным. Администрирование публичного учебного HTTP-стенда лучше выполнять через SSH-туннель; для постоянного рабочего использования нужны HTTPS и авторизация пользователей.

```bash
# Состояние и диагностика
docker compose ps
docker compose logs --tail=50

# Перезапуск с сохранением данных
docker compose restart

# Остановка с сохранением volumes
docker compose down

# Восстановление после перезагрузки сервера происходит по restart: unless-stopped.
# Если стек был остановлен вручную:
docker compose up -d --build
```

Для резервной копии остановите только этот Compose-проект, сохраните оба его volumes, конфигурацию и `.env`, затем снова запустите его. `docker compose down -v` удаляет учебные данные без возможности восстановления из самого стека — используйте только при намеренном полном сбросе. Обычный `down` сохраняет volumes.

Официальная документация: [Provisioning Grafana](https://grafana.com/docs/grafana/latest/administration/provisioning/), [Loki retention](https://grafana.com/docs/loki/latest/operations/storage/retention/), [Filesystem storage](https://grafana.com/docs/loki/latest/operations/storage/filesystem/).
